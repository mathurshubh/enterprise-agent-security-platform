# 02 — Design Principles

## Purpose

This document defines the **10 permanent architectural principles** governing every user interface, data flow, component design, and state management decision across the Enterprise Security Console.

---

## Scope

These principles apply to all code within `frontend/src/` and all future frontend modules. They bind all human and AI contributors to immutable design invariants.

---

## The 10 Governing Principles

### 1. Backend Is Truth
The console never computes, infers, or fabricates security data. The client UI is a pure presentation layer. If a backend API endpoint does not exist or returns an empty payload, the console displays a degraded or empty state—it **never** calculates synthetic risk scores, mock decision statuses, or estimated metrics.

> **Rationale:** Fabricating security state in client code violates the platform's core Zero Trust principle ([ADR-001](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-001-zero-trust-security-model.md)) and misleads security analysts during live incidents.

### 2. Zero Trust Client
The browser environment is treated as untrusted. No platform secrets, API signing keys, or authorization decision logic reside in client code. Every client request passes through authenticated API gateways, and client-side UI visibility controls are purely cosmetic—authoritative access control is strictly enforced by the backend API.

> **Rationale:** Aligns with [ADR-001](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-001-zero-trust-security-model.md) and [ADR-009](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-009-enterprise-security-console.md).

### 3. Decisions Are Read-Only
Security decisions generated by the backend (authorization denials, policy checks, threat rule firings, risk scores, enforcement actions) are immutable evidence. The console provides **zero affordances** to edit, override, or delete historical security decisions.

> **Rationale:** Preserves audit trail integrity and evidentiary non-repudiation as mandated by [ADR-014](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-014-behavioral-intelligence-and-autonomous-agent-governance.md) and [ADR-016](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-016-behavioral-event-store-and-data-model.md).

### 4. Operator Commands Are Audited Writes
The console performs write operations **only** for explicit administrative governance actions (e.g., releasing a held session in the Approval Queue, closing an incident case, or attaching an analyst note). These actions are sent as structured, audited commands to backend endpoints, which perform authorization checks, record an immutable audit event, and return the authoritative outcome.

> **Rationale:** Complies with [ADR-020](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-020-agent-security-operations.md) for human-in-the-loop SOC operations.

### 5. Temporal First
Autonomous agent behavior unfolds over time across multi-step execution sessions. The console prioritizes temporal representations (timelines, execution sequences, risk score evolution curves) over static point-in-time snapshots.

> **Rationale:** Behavioral intelligence ([ADR-014](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-014-behavioral-intelligence-and-autonomous-agent-governance.md)) and sequential detection ([ADR-017](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-017-behavioral-detection-engine.md)) can only be evaluated in sequence context.

### 6. Session-Centric Investigation
The agent session is the fundamental operational unit of investigation. All forensic workflows, event traces, finding evaluations, and risk trajectory curves converge on the **Session Investigation Workspace**.

> **Rationale:** Single tool invocations lack context; an entire session captures the full causal chain from prompt to tool execution to enforcement.

### 7. Evidence Chain Navigation
Every rendered artifact contains hyperlinked references to its upstream producers and downstream consumers along the Canonical Investigation Graph. Clicking a Behavioral Finding navigates to its producing Behavioral Events; clicking a Risk Assessment navigates to its contributing Findings and triggering Enforcement Decision.

> **Rationale:** Eliminates manual ID copy-pasting and enables rapid cross-entity context switching during SOC triage.

### 8. Incremental Evolution
All architectural updates to the user interface must be strictly additive. Existing URLs, API service wrappers, and page routes are preserved. New operational capabilities slot into the established navigation framework without breaking existing deep links or user workflows.

> **Rationale:** Follows repository engineering standards defined in [AGENTS.md](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/AGENTS.md).

### 9. Untrusted Content Isolation
All dynamic data originating from external or LLM sources (user prompts, model reasoning text, raw tool outputs, external API payloads) are treated as untrusted. They are visually isolated using distinct container styling (monospaced font, bordered containers, explicit untrusted labels) and rendered safely using strict output escaping.

> **Rationale:** Protects security analysts against indirect prompt injection or visual spoofing embedded within agent execution logs ([ADR-002](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-002-llm-untrusted-intent-parser.md), [ADR-009](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-009-enterprise-security-console.md)).

### 10. Graceful Degradation
When backend services or optional Behavioral Intelligence modules are unavailable, the console displays clear degraded-status indicators. Baseline management capabilities (listing registered agents, inspecting static tools, viewing audit logs) remain fully functional even if advanced telemetry or streaming feeds are offline.

> **Rationale:** Mirrors backend non-blocking telemetry and fail-degraded security pipeline principles ([ADR-015](file:///Users/shubhankarmathur/projects/enterprise-agent-security-platform/docs/adr/ADR-015-behavioral-telemetry-architecture.md)).

## Design Rationale

Establishing explicit design principles prevents architectural drift during incremental feature development. Principles 1–4 enforce Zero Trust trust boundaries between the client UI and the backend security pipeline. Principles 5–7 optimize analyst efficiency during incident investigation. Principles 8–10 ensure frontend reliability, safety, and backwards compatibility.

---

## Tradeoffs

- **Strict Client Constraints:** Developers cannot quickly add "quick fix" client-side calculations or local state overrides; all data must be backed by official backend API contracts.
- **Visual Overhead:** Untrusted content isolation and evidence chain links add visual density to table rows and detail drawers.
